# Compatibility contract

The pinned reference CLI is `proselint` (also available as `python -m proselint`). It supports `check`, `version`, and `dump-config`; `check` accepts configuration and output-format options, files or directories, and stdin. Directory traversal, text decoding, newline handling, quote suppression, match positions, maximum finding limits, sorting, and serialization each have observable behavior that must be checked against the live reference before claiming compatibility.

The pinned inventory contains 124 registered entries across 106 unique check paths, including duplicate paths, helper types, matcher options, flags, offsets, and data fields. See [`../inventory.json`](../inventory.json).

## Verified scope

The Rust port currently has 51 accepted capabilities with 438 live compatibility cases. Coverage includes bounded JSON CLI behavior, selected-rule configurations, and a set of individual rules. The exact accepted rules, cases, and evidence are recorded in [`../status.json`](../status.json) and live reports under [`../artifacts/`](../artifacts/). Configuration coverage includes Python-compatible JSON syntax errors (22 cases), invalid UTF-8 error objects (five cases), recursion/deep-value behavior (12 cases), five ignored-value cases, and 12 consumed-special-value cases. The consumed cases preserve Python’s type-specific failures for the tested `NaN`, overflow float, and lone-surrogate contexts.

## Unverified scope

The cumulative live gate passed 438 accepted cases; see [`../artifacts/strict-gate-phrasal-adjectives-accepted-20261106.json`](../artifacts/strict-gate-phrasal-adjectives-accepted-20261106.json). Cwd/ancestor and XDG/HOME discovery independently passed 16 cases, including precedence, relative XDG paths, unset/empty XDG fallback, and malformed-winner behavior; see [`../artifacts/independent-ancestor-discovery-20261106/ancestor-discovery-live.json`](../artifacts/independent-ancestor-discovery-20261106/ancestor-discovery-live.json) and [`../artifacts/independent-user-discovery-20261106/cli-config-user-discovery.json`](../artifacts/independent-user-discovery-20261106/cli-config-user-discovery.json). The accepted cases do not cover the entire default configuration, every registered check, every file traversal and decoding edge case, no-config-found bundled defaults, missing nonempty-XDG configuration, HOME-unset platform home resolution, directory user candidates, all error and multi-file behavior, Compact output, file-path/multi-file Full rendering, omitted parser options beyond output format, or non-Linux filesystem error formatting. Unicode and ordering behavior outside explicitly covered cases also remains unverified. Treat uncovered behavior as unknown; do not infer full parity from isolated rule or CLI passes.

The inventory contains 67 unique check paths that are not yet accepted. The 444-case manifest includes four per-file configuration cases and two harness smoke cases outside production comparison. Earlier evidence is [`../artifacts/independent-review-fixes/final-gate-348.json`](../artifacts/independent-review-fixes/final-gate-348.json) and the separate [per-file comparison](../artifacts/independent-review-fixes/per-file-targeted-348.json). These results do not establish full CLI or rule-inventory parity.

Every compatibility claim requires a fresh live comparison with the pinned Python executable. Cached snapshots are useful evidence for review but cannot establish parity by themselves.
