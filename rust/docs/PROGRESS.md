# Migration progress

## Current state

- Updated process cadence: keep focused Rust/live parity and an independent focused verifier for every capability; batch the cumulative live gate every 5–10 recorded capabilities, before release, and immediately after shared matcher/config/CLI/output changes. This should cut cumulative-gate invocations by about 80–90% versus running one after every capability in a stable batch, while preserving the per-capability checks. Stage durations and case counts are now required in each capability record. Benchmarking stays separate, with exact-workload live preflight and a whole-run deadline. POSIX process groups are terminated on timeout; detached descendants and the current Windows direct-child-only cleanup remain limits.
- Process-change validation: 52 comparator and benchmark harness tests passed in 10.110s; 23 live comparator negative/self checks passed; docs whitespace and JSON syntax checks passed. Candidate fingerprints now ignore Markdown docs, inventory, and status/history ledgers while still tracking source, tests, harness, manifests, and Cargo inputs; each gate report records its exact capability/case scope. This avoids metadata-only candidate invalidation. The latest official cumulative gate took 214.432s, so batching a stable 5–10-capability interval avoids an estimated four to nine redundant runs, about 14.3–32.2 minutes, while retaining focused live and independent verification for every capability. This estimate excludes mandatory gates after shared matcher/config/CLI/output changes.
