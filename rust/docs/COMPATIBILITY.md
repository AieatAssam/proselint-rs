# Compatibility contract

The pinned reference CLI is `proselint` (also available as `python -m proselint`). It supports `check`, `version`, and `dump-config`; `check` accepts configuration and output-format options, files or directories, and stdin. Directory traversal, text decoding, newline handling, quote suppression, match positions, maximum finding limits, sorting, and serialization each have observable behavior that must be checked against the live reference before claiming compatibility.

The pinned inventory contains 124 registered entries across 106 unique check paths, including duplicate paths, helper types, matcher options, flags, offsets, and data fields. See [`../inventory.json`](../inventory.json).

## Verified scope

The Rust port currently has 118 accepted capabilities with 1003 live compatibility cases, including 83 unique rule paths and bounded CLI behavior. Plain-text `version` and `--version` print `Proselint 0.16.0`; root `--version` and a valid root `--output-format` before `check` are overridden by the check parser defaults, malformed root output-format values retain argparse errors, and `check --version` still prints the version; top-level `--help`, `-h`, and no-argument behavior match exact output/status cases; `version --help` and `dump-config --help` match pinned output too; `check --help` and `check -h` also match exactly. Three recorded combinations of `check --help` with a later path or missing config match the same 774-byte help output, status 0, and empty stderr. Four argument-precedence cases also match exactly: missing check `--config` value before help, invalid output format before help, global `--config check --help`, and a real `--help` path after `--`. Missing `--help` after `--` also matches in Full and Compact stderr and JSON file-error output. Explicit multi-file inputs match argv order, per-file `max_errors`, Full/Compact/JSON output, and JSON continuation after a missing path; a separate live regression confirms Full missing-path output uses the resolved path and continues with later files. . Invalid UTF-8 file input produces matching Full per-file text and JSON `UnicodeDecodeError` results; Compact has a separate accepted error case. Directory inputs recursively expand accepted `.md`, `.txt`, `.rtf`, `.html`, `.tex`, and `.markdown` files in filesystem enumeration order, with exact-case suffix filtering and per-file output handling. Selected-rule `check --demo` matches in Compact output. Coverage includes selected-rule configurations; the full default configuration and all registered rules have not yet passed acceptance. The exact accepted rules, cases, and evidence are recorded in [`../status.json`](../status.json) and live reports under [`../artifacts/`](../artifacts/). Configuration coverage includes empty-HOME passwd-home fallback under a recorded clean-home precondition, Python-compatible JSON syntax errors (22 cases), invalid UTF-8 error objects (five cases), recursion/deep-value behavior (12 cases), five ignored-value cases, and 12 consumed-special-value cases. The consumed cases preserve Python’s type-specific failures for the tested `NaN`, overflow float, and lone-surrogate contexts.
