# Compatibility contract

The pinned reference CLI is `proselint` (also available as `python -m proselint`). It supports `check`, `version`, and `dump-config`; `check` accepts configuration and output-format options, files or directories, and stdin. Directory traversal, text decoding, newline handling, quote suppression, match positions, maximum finding limits, sorting, and serialization each have observable behavior that must be checked against the live reference before claiming compatibility.

The pinned inventory contains 124 registered entries across 106 unique check paths, including duplicate paths, helper types, matcher options, flags, offsets, and data fields. See [`../inventory.json`](../inventory.json).

## Verified scope

The Rust port currently has 107 accepted capabilities with 935 live compatibility cases, including 83 unique rule paths and bounded CLI behavior. Plain-text `version` and `--version` print `Proselint 0.16.0`; top-level `--help`, `-h`, and no-argument behavior match exact output/status cases; `version --help` and `dump-config --help` match pinned output too; `check --help` and `check -h` also match exactly. Three recorded combinations of `check --help` with a later path or missing config match the same 774-byte help output, status 0, and empty stderr. Selected-rule `check --demo` matches in Compact output. Coverage includes selected-rule configurations; the full default configuration and all registered rules have not yet passed acceptance. The exact accepted rules, cases, and evidence are recorded in [`../status.json`](../status.json) and live reports under [`../artifacts/`](../artifacts/). Configuration coverage includes Python-compatible JSON syntax errors (22 cases), invalid UTF-8 error objects (five cases), recursion/deep-value behavior (12 cases), five ignored-value cases, and 12 consumed-special-value cases. The consumed cases preserve Python’s type-specific failures for the tested `NaN`, overflow float, and lone-surrogate contexts.

## Unverified scope

The latest strict cumulative gate passes 935/935 production comparisons across 107 accepted capabilities from 937 manifest cases; only the two harness smoke cases are excluded. It took 353.671s, including 315.242s for live comparisons and 36.009s for Rust checks/build; comparator checks passed 23/23 and oracle integrity passed. See [`../artifacts/strict-gate-help-combined-scope-guard-final-20261107.json`](../artifacts/strict-gate-help-combined-scope-guard-final-20261107.json). Cwd/ancestor and XDG/HOME discovery independently passed 16 cases, including precedence, relative XDG paths, unset/empty XDG fallback, and malformed-winner behavior; see [`../artifacts/independent-ancestor-discovery-20261106/ancestor-discovery-live.json`](../artifacts/independent-ancestor-discovery-20261106/ancestor-discovery-live.json) and [`../artifacts/independent-user-discovery-20261106/cli-config-user-discovery.json`](../artifacts/independent-user-discovery-20261106/cli-config-user-discovery.json). The accepted cases do not cover the entire default configuration or every registered check. No-config fallback is verified only for three probe inputs and 83 implemented rule paths; the 23 remaining rule paths keep full default behavior incomplete. Missing nonempty-XDG configuration, HOME-unset platform home resolution, directory user candidates, missing non-JSON explicit-config errors are covered for Full and Compact, but all error and multi-file behavior and other Compact output behavior, file-path/multi-file Full rendering, omitted parser options beyond output format, and non-Linux filesystem error formatting remain incomplete or unverified. JSON version metadata, combined `--version` arguments, short help for other subcommands, and other combinations of help with arguments remain unverified. For `cli.help_combined_arguments`, the accepted three cases match exactly, but independent guard probes differed for a missing option value before help, invalid format before help, a config value named `check`, and `--` terminator behavior; those probes are not accepted. Default-config demo output remains incomplete because it exercises unimplemented rules; Full/JSON demo source paths remain unverified because they expose the package-specific absolute path. Unicode and ordering behavior outside explicitly covered cases also remains unverified. Treat uncovered behavior as unknown; do not infer full parity from isolated rule or CLI passes.

The inventory contains 23 unique rule paths that remain unimplemented. The 937-case manifest has 935 production comparisons; only two harness smoke cases are excluded. The latest additions include `cli.check_help`, `cli.command_help`, `cli.help_combined_arguments`, and selected-rule Compact `cli.check_demo_compact_selected_rules`. The port remains partial and does not establish full CLI or default-rule parity.

Every compatibility claim requires a fresh live comparison with the pinned Python executable. Cached snapshots are useful evidence for review but cannot establish parity by themselves.
